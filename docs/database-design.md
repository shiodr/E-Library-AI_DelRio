# PostgreSQL database design

All IDs are UUID primary keys generated by the application. Timestamps are timezone-aware.
The initial migration creates the five requested tables plus Alembic's version table.

Migration `0003` adds two owner-protected assistant tables and administrator import
protection. `assistant_conversations` stores an owner ID, bounded JSON history, and
timestamps; a check permits exactly one registered-user or guest-session owner.
`assistant_rate_limits` stores shared per-owner/global counters and window timestamps.
`books.is_managed_by_admin` and immutable `seed_source_url` preserve administrator
edits and archives when the bootstrap manifest is reapplied. Existing library rows
and foreign-key identities are retained. See the [current handoff](phase1-completion.md).

| Table | Fields and constraints |
| --- | --- |
| `users` | `id`, `full_name`, unique/indexed normalized `email`, `password_hash`, checked `role` (`reader`/`admin`), `created_at`, `updated_at` |
| `sessions` | `id`, nullable/indexed `user_id`, unique `session_token_hash`, checked `session_type`, indexed `expires_at`, nullable `revoked_at`, `created_at` |
| `books` | `id`, indexed `title`, indexed `author`, indexed `category`, `description`, nullable `cover_url`, unique `source_url`, `license_type`, checked `access_type`, indexed `is_active`, `created_at`; unique title/author pair |
| `favorites` | `id`, indexed `user_id`, indexed `book_id`, `created_at`; unique user/book pair |
| `downloads` | `id`, nullable/indexed `user_id`, nullable/indexed `guest_session_id`, indexed `book_id`, `downloaded_at`; exactly one owner, unique owner/book pairs |

Session identity has a database check: a guest has no `user_id`; a user session must
reference a registered user. Guest identity is the session itself, not a fake user row.
Deleting a user cascades sessions/favorites/download history. A downloaded book cannot
be deleted while referenced (`RESTRICT`); favorites cascade with book deletion.
The ORM updates `users.updated_at` on account updates. External SQL writers must update
that timestamp themselves until a database trigger is introduced if needed.

## Migration and seed

From `backend`, with the configured virtual environment active:

```bash
python -m alembic upgrade head
python -m app.services.seed
python -m alembic current
```

Migration `0002` adds `access_type` (`free_to_read`/`paid`) and `is_active`, with defaults
that preserve existing readers and rows. `seed` validates the reviewed 200-title
programming manifest, then upserts metadata by source URL while retaining existing IDs.
The original eight Gutenberg sample rows are archived, preserving references and
allowance usage. Other maintained records are left untouched. Descriptions and cover
designs are original; source links and access terms distinguish free online editions
from paid publisher listings. No book files are imported. See [catalog provenance](programming-catalog.md).

Downgrading only to `0001` removes these two metadata fields but retains book/user/history
rows. It does not restore the original catalog and cannot run under the current API.
The isolated test suite verifies downgrade, preservation, re-upgrade, and reclassification.

Rollback is `python -m alembic downgrade base`. It drops all application tables and their data;
use only on a disposable database, or after a verified backup. The test suite proves
both downgrade and upgrade on a dedicated `_test` database.

## Implemented download tracking transaction

The API derives ownership from the validated session, never from a supplied user ID.
For registered accounts, lock the user row with `SELECT ... FOR UPDATE`; for guests,
lock the guest session row and verify `session_type == 'guest'`. Inside that same
transaction, count distinct downloaded books, return an existing record idempotently,
and reject a new record after five guest books or ten registered books. The unique
constraints prevent duplicates; row locks prevent simultaneous requests from exceeding
the allowance. Session expiry is rechecked after waiting for the account lock.
Tracking records an approved request; file storage/streaming and source/license checks
for future hosted files must be added before issuing controlled file URLs.

Limits apply per guest session and per registered account across devices. Repeated
downloads of one book will not consume another slot. Guest session reset can reset
its allowance by design; abuse prevention and any stronger policy require a separate
product decision. `POST /api/v1/downloads` enforces these limits on tracking requests;
it does not claim to control access to external public-domain source websites.

Favorites now use the same registered-account locks for concurrent add/delete operations.
Future AI saves must share these authorized services, ownership rules,
and database transactions as normal UI actions. The current My Library screen presents
download-tracking history, while Favorites presents saved books. Introduce a separate
`library_items` table only if future requirements need another kind of membership.

The catalog has no artificial eight-book or 200-book database cap. Current B-tree
indexes support sort/category queries; substring `ILIKE` search is adequate for a few
hundred rows. Consider PostgreSQL full-text/trigram indexes only after measuring need.
